# 权限命名标准化报告

## 项目概述

针对线索申报系统中权限命名混乱的问题，我们进行了全面的分析和标准化工作。本报告详细记录了当前状况、解决方案和实施计划。

## 当前状况分析

### 权限命名现状
- 系统中存在多种权限命名格式
- 部分权限缺少域前缀（如 `user:add`）
- 部分权限已符合规范（如 `business:contract:template:add`）
- 总计约 100+ 个权限标识

### 存在的问题
1. **格式不统一**：权限标识格式多样，缺乏统一规范
2. **域标识缺失**：系统管理类权限缺少 `system:` 前缀
3. **可维护性差**：不规范的命名增加了维护难度
4. **扩展性受限**：缺乏标准导致新增权限命名随意

## 解决方案

### 1. 权限命名规范
我们制定了统一的权限命名规范：

```
域:模块:功能:操作    # 四段式（推荐用于复杂业务操作）
域:模块:操作        # 三段式（推荐用于简单系统操作）
```

- **域（Domain）**：
  - `system`: 系统管理功能
  - `business`: 业务功能
  - `workflow`: 工作流功能

- **模块（Module）**：小写字母，多词用连字符
- **功能（Feature）**：可选，表示具体功能模块
- **操作（Action）**：标准操作词汇

### 2. 标准词汇表
- 查询类：`list`, `query`, `view`, `detail`
- 操作类：`add`, `update`, `delete`, `edit`
- 业务类：`submit`, `approve`, `audit`, `generate`

- 全面测试权限控制功能
- 验证各角色权限分配

## 预期收益

1. **提高可维护性**：统一的命名规范便于理解和维护
2. **增强一致性**：所有权限标识遵循相同标准
3. **改善扩展性**：新权限按规范创建，保持一致性
4. **降低错误率**：减少因命名混乱导致的配置错误
